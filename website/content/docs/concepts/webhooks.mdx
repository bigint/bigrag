Webhooks push notifications when document processing state changes. They're useful for triggering downstream workflows when documents are ready for search.

## Events

| Event | Description |
|-------|-------------|
| `document.processing` | Document processing has started |
| `document.ready` | Document successfully processed, now searchable |
| `document.failed` | Document processing failed |

## Registering a Webhook

```bash
curl -X POST http://localhost:4000/v1/admin/webhooks \
  -H "Authorization: Bearer $RAG_COMPUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://example.com/webhook",
    "events": ["document.ready", "document.failed"],
    "collections": ["knowledge_base"],
    "description": "Notify on document processing"
  }'
```

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `url` | string | yes | Delivery URL (HTTPS required, HTTP allowed for localhost) |
| `events` | string[] | yes | Event types to subscribe to |
| `collections` | string[] | no | Filter by collection names (`null` = all) |
| `description` | string | no | Human-readable description |

<Callout type="warn">
  The response includes a `secret` field that is shown only once. Store it — it's used to verify webhook signatures.
</Callout>

## Payload Format

```json
{
  "event": "document.ready",
  "timestamp": "2026-04-02T12:34:56Z",
  "collection": "docs",
  "document_id": "abc-123",
  "status": "ready",
  "chunk_count": 42,
  "error_message": null
}
```

## Signature Verification

Each delivery includes an `X-Rag-Computer-Signature` header with an HMAC-SHA256 signature:

```
X-Rag-Computer-Signature: sha256=<hex digest>
X-Rag-Computer-Event: document.ready
X-Rag-Computer-Delivery: <delivery-uuid>
```

Verify by computing `HMAC-SHA256(webhook_secret, raw_body)`:

```python
import hashlib
import hmac

def verify(payload: bytes, secret: str, signature: str) -> bool:
    expected = "sha256=" + hmac.HMAC(
        secret.encode(), payload, hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(expected, signature)
```

## Retry Policy

Failed deliveries retry 3 times with exponential backoff (~10s, ~30s, ~90s). After all retries, the delivery is marked as `failed`.

Check delivery history:

```bash
curl http://localhost:4000/v1/admin/webhooks/{id}/deliveries \
  -H "Authorization: Bearer $RAG_COMPUTER_API_KEY"
```

## Testing

Send a `webhook.test` event to verify your endpoint is reachable:

```bash
curl -X POST http://localhost:4000/v1/admin/webhooks/{id}/test \
  -H "Authorization: Bearer $RAG_COMPUTER_API_KEY"
```

## Limits

- Maximum 50 webhooks per instance
- Delivery timeout: 10 seconds (configurable via `RAG_COMPUTER_WEBHOOK_DELIVERY_TIMEOUT`)
