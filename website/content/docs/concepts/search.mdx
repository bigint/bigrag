bigRAG exposes three base search modes plus four query-time modifiers. The modifiers compose: you can hybrid-search with MMR diversity, facets, and reranking all in the same call.

## Modes

| Mode | Description |
|------|-------------|
| `semantic` | Default. Cosine similarity against stored vectors. |
| `keyword` | Text-based matching using term frequency. No embedding involved. |
| `hybrid` | Runs semantic and keyword in parallel; merges with Reciprocal Rank Fusion (RRF). |

### Semantic

```bash
curl -X POST http://localhost:4000/v1/collections/docs/query \
  -H "Authorization: Bearer $BIGRAG_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"query": "What are the main findings about climate change?"}'
```

Best for natural language questions and conceptual queries.

### Keyword

```bash
curl -X POST http://localhost:4000/v1/collections/docs/query \
  -H "Authorization: Bearer $BIGRAG_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"query": "ERR-4021", "search_mode": "keyword"}'
```

Best for exact terms, product codes, IDs, proper nouns.

### Hybrid

```bash
curl -X POST http://localhost:4000/v1/collections/docs/query \
  -H "Authorization: Bearer $BIGRAG_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"query": "error code ERR-4021 authentication", "search_mode": "hybrid"}'
```

Best for queries that mix natural language with specific terms.

## Query parameters

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `query` | string | — | Required query text |
| `top_k` | integer | Collection default | 1–1,000 |
| `filters` | object | — | Metadata filters — see below |
| `min_score` | float | Collection default | Drop hits below this score |
| `search_mode` | string | Collection default | `semantic`, `keyword`, `hybrid` |
| `rerank` | boolean | Collection setting | Force Cohere rerank on/off |
| `diversity` | float (0–1) | — | MMR diversity weight |
| `hyde` | boolean | `false` | Generate a HyDE hypothetical document |
| `facets` | string[] | — | Metadata keys to aggregate |
| `use_semantic_cache` | boolean | `true` | Replay near-duplicate queries |

## Filters

Pass a plain value for exact match, or use operators for more control.

```json
{ "filters": { "author": "Smith", "year": 2026 } }
```

| Operator | Description | Value Type |
|----------|-------------|------------|
| `$eq` | Equal | string, number, boolean |
| `$ne` | Not equal | string, number, boolean |
| `$gt` | Greater than | number |
| `$gte` | Greater than or equal | number |
| `$lt` | Less than | number |
| `$lte` | Less than or equal | number |
| `$in` | In list | array of strings or numbers |

```json
{
  "filters": {
    "year": { "$gte": 2024 },
    "status": { "$in": ["published", "preprint"] },
    "score": { "$gt": 0.8 }
  }
}
```

Multiple filters are combined with AND. When a collection was created with `tenant_field`, setting that field in `filters` routes the query to a Milvus partition — 10–50× faster than scalar filtering at scale.

## Reranking

When `reranking_enabled` is set on a collection, retrieved hits are re-scored by a Cohere cross-encoder (`rerank-v3.5` by default). Override per query with `"rerank": false` to measure lift, or `"rerank": true` on a collection that has it disabled.

## MMR diversity

`diversity` turns on Maximal Marginal Relevance re-ranking, a cheap local pass that avoids near-duplicate hits:

```json
{ "query": "error handling patterns", "top_k": 20, "diversity": 0.4 }
```

- `0.0` — pure relevance (default hit order)
- `1.0` — pure diversity (minimally overlapping snippets)
- `0.3–0.5` — useful middle ground for most Q&A

MMR runs after reranking but before the cache write.

## HyDE (Hypothetical Document Embeddings)

Set `"hyde": true` to generate a short hypothetical answer, embed **that**, and search. Improves recall on sparse / keyword-poor questions where the raw query is far from any stored chunk. Adds one LLM call of latency (`hyde_ms` in the response `timings`).

```json
{ "query": "Why does HNSW recall collapse at high dimensions?", "hyde": true }
```

## Facets

Pass metadata keys you want aggregated alongside the hits:

```json
{ "query": "climate change", "facets": ["author", "year"] }
```

Response includes:

```json
"facets": {
  "author": [{"value": "Smith", "count": 8}, {"value": "Jones", "count": 2}],
  "year":   [{"value": 2024, "count": 6}, {"value": 2025, "count": 4}]
}
```

Facet counts are scoped to the current result set, **not** the whole collection — so applying a filter tightens them.

## Semantic cache

Identical / near-duplicate queries within the cache window replay the stored response. The response reports `"cached": true`. Turn it off with `"use_semantic_cache": false` when benchmarking or when you really want a fresh embed (e.g., right after a reprocess).

## Timings

Every response includes a `timings` breakdown — stages that didn't run report `0`:

```json
"timings": {
  "embed_ms": 18.2,
  "search_ms": 12.4,
  "rerank_ms": 31.5,
  "hyde_ms": 0,
  "mmr_ms": 0.4,
  "total_ms": 62.8
}
```

## Multi-Collection Query

```bash
curl -X POST http://localhost:4000/v1/query \
  -H "Authorization: Bearer $BIGRAG_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"query":"machine learning","collections":["docs","papers"],"top_k":20}'
```

Each result includes a `collection` field. Useful when you've split content across collections by domain, tenant, or embedding model and want one unified answer.

## Batch Query

Up to 20 independent queries, executed in parallel:

```bash
curl -X POST http://localhost:4000/v1/batch/query \
  -H "Authorization: Bearer $BIGRAG_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "queries": [
      {"collection": "docs", "query": "authentication", "top_k": 5},
      {"collection": "papers", "query": "neural networks", "top_k": 10, "search_mode": "hybrid"}
    ]
  }'
```

## Analytics

```bash
curl http://localhost:4000/v1/collections/docs/analytics \
  -H "Authorization: Bearer $BIGRAG_API_KEY"
```

Returns 24h / 7d / 30d aggregates — query count, average latency, average score, top queries. Cached for five minutes.
