Studio is the Next.js admin UI packaged with bigRAG. Every control is also a REST API, so Studio is optional — you can run bigRAG headless — but it's the fastest way to bootstrap, prototype, and operate the platform.

## Running Studio

```bash
pnpm dev:app        # Studio on http://localhost:3000
```

Studio proxies every request through `/api/bigrag/[...path]` onto the backend (default `http://localhost:4000`). Session cookies are forwarded automatically.

## Route map

| Path | Purpose |
|------|---------|
| `/setup` | One-time page to create the first admin account. Disappears once `needs_setup: false`. |
| `/login` | Email + password login for admins and members. |
| `/overview` | Platform-wide stats — collection count, document states, queue depth, readiness. |
| `/collections` | List, create, delete, and search collections. |
| `/collections/[name]` | Redirects to the collection's documents tab. |
| `/collections/[name]/documents` | Upload (drag & drop or multi-file picker), list, inspect status, and delete documents. |
| `/collections/[name]/documents/[docId]` | Document detail — chunk viewer, live progress, failed-ingest error, reprocess, and delete. |
| `/collections/[name]/search` | Query tester scoped to the collection — tweak `search_mode`, `top_k`, and rerank when enabled. |
| `/collections/[name]/settings` | Edit description, metadata, metadata schema, reranking, chunking, and default query params. |
| `/collections/[name]/s3-jobs` | Manage S3 bucket-ingestion jobs for a collection. |
| `/playground` | Chat-like playground; retrieve from one collection, then stream an OpenAI answer from the browser using your saved playground key. |
| `/models` | Manage [embedding presets](/docs/api-reference/embedding-presets) — reusable provider + model + key tuples. |
| `/mcp` | Mint, scope, rotate, and revoke [MCP server](/docs/api-reference/mcp-servers) credentials for Claude Desktop / Cursor / custom MCP clients. |
| `/api-keys` | Mint, scope, rate-limit, and revoke `bigrag_sk_…` keys. Plaintext shown once at creation. |
| `/webhooks` | Register, test, and delete webhooks. Delivery history and replay are available through the API. |
| `/settings` | Tabs: Account · Server · Usage & cost · Audit log. |
| `/evals` | Run golden-set retrieval evaluations. |

## Settings tabs

| Tab | Reads from | Writes to |
|-----|-----------|-----------|
| **Account** | `GET /v1/auth/me` | `POST /v1/auth/password`, `POST /v1/auth/logout-all` |
| **Server** | `GET /health/ready`, `GET /v1/stats` | — |
| **Usage & cost** | `GET /v1/usage` | — |
| **Audit log** | `GET /v1/admin/audit` | — |

## Real-time progress

Studio subscribes to `GET /v1/collections/{name}/documents/{doc_id}/progress` on the document detail page while a document is pending or processing. The API also exposes `GET /v1/collections/{name}/events` for collection-wide document activity if you are building your own dashboard.

## Playground specifics

The playground sends a single-collection retrieval request to `POST /v1/collections/{name}/query`, renders retrieved chunks and timings, and then calls OpenAI directly from the browser with your saved playground key. Preferences such as OpenAI key, model, temperature, `top_k`, and system prompt persist via `/v1/auth/preferences`.

### Citations

Retrieved chunks carry citation provenance — `document_id`, `chunk_index`, and Docling-derived `page_no` / `char_start` / `char_end` (see [`QueryResult`](/docs/api-reference/query)). The playground hands every chunk to the LLM as `[N] (filename, page X) <text>` and instructs the model to cite with bracketed numbers. In the rendered answer, every `[N]` token is a clickable link that expands the **View sources** panel and scrolls to the matching source card; the card itself shows the document filename, chunk index, page badge, and character offsets when present.

<Callout type="info">
Studio uses session cookies exclusively. To automate anything Studio does, mint an API key at `/api-keys` and use it with one of the [SDKs](/docs/sdks/typescript) — or with raw HTTP using the same REST endpoints.
</Callout>

## When to skip Studio

- **Pure backend deployment** — no Studio process, everything via API keys and SDKs. Set `BIGRAG_ENV=prod` and use [`POST /v1/auth/setup`](/docs/api-reference/authentication) from an admin workstation to bootstrap.
- **Embedded experiences** — if you're surfacing search inside your own app, skip Studio and build against the [query API](/docs/api-reference/query).
- **Read-only operators** — create a `member` account; they get `/overview`, `/collections` (read), and `/playground` but can't mutate.
