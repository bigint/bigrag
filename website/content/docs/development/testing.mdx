## Local checks

Run the backend tests from `api/`:

```bash
uv run pytest tests/ -q
uv run pytest tests/ --cov --cov-report=term-missing
uv run ruff check .
uv run ruff format --check .
```

Run TypeScript and admin UI checks from the repository root:

```bash
pnpm --filter @bigrag/client test
pnpm --filter @bigrag/client coverage
pnpm --filter @bigrag/app test
pnpm --filter @bigrag/app coverage
pnpm typecheck
pnpm exec biome check .
```

Run SDK-specific checks:

```bash
cd sdks/python && uv sync --dev && uv run pytest -q
cd sdks/python && uv run pytest --cov --cov-report=term-missing
cargo test --manifest-path sdks/rust/Cargo.toml
```

## Coverage reports

Coverage commands print a terminal percentage and can write HTML reports for local inspection:

| Area | Command | HTML output |
| --- | --- | --- |
| Backend API | `cd api && uv run pytest tests/ --cov --cov-report=term-missing --cov-report=html` | `api/htmlcov/index.html` |
| Python SDK | `cd sdks/python && uv run pytest --cov --cov-report=term-missing --cov-report=html` | `sdks/python/htmlcov/index.html` |
| TypeScript SDK | `pnpm --filter @bigrag/client coverage` | `sdks/typescript/coverage/index.html` |
| Admin UI | `pnpm --filter @bigrag/app coverage` | `app/coverage/index.html` |

Run the docs build:

```bash
pnpm --filter @bigrag/docs build
```

## Coverage expectations

Backend route tests should use dependency overrides and fake service/session objects unless the scenario is specifically testing live infrastructure integration.

Ingestion queue tests should stay dependency-free by default. Cover Redis state helpers, conversion helpers, embedding/vector payload behavior, and orchestration regressions with fake Redis, storage, embedding, and vector-store objects unless a test explicitly opts into live infrastructure.

SDK tests should exercise request construction, retries, error mapping, multipart uploads, SSE parsing, and resource namespace path/query/body shaping as runtime behavior, not only typechecking.

Admin UI tests should cover pure utilities, query-key builders, API helpers, and toast/error adapters first. UI workflows should be added when component behavior becomes risky enough to justify browser-oriented tests.
