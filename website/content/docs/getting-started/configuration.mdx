bigRAG uses a UI-first configuration model. Operators provide only the wiring needed before the API can read Postgres, then admins manage product/runtime settings from `/settings`.

Auth is admin accounts + session cookies and minted `bigrag_sk_…` API keys — see [Authentication](/docs/api-reference/authentication).

## Bootstrap config

Bootstrap config is the small set of values the API needs before it can connect to the database and decrypt saved settings.

| Variable | Description | Default |
|----------|-------------|---------|
| `BIGRAG_ENV` | `dev` or `prod`. Production mode enforces safe startup checks. | `dev` |
| `BIGRAG_HOST` | API bind address. | `127.0.0.1` |
| `BIGRAG_PORT` | API bind port. | `4000` |
| `BIGRAG_WORKERS` | Uvicorn process count. | `1` |
| `BIGRAG_DATABASE_URL` | Postgres connection URL. | `postgres://bigrag:bigrag@localhost:5432/bigrag?sslmode=disable` |
| `BIGRAG_DB_POOL_MIN` | Minimum Postgres pool size. | `5` |
| `BIGRAG_DB_POOL_MAX` | Maximum Postgres pool size. | `50` |
| `BIGRAG_MIGRATION_TIMEOUT_SECONDS` | Startup migration timeout. Set `0` to disable the timeout. | `60` |
| `BIGRAG_REDIS_URL` | Redis connection URL. | `redis://localhost:6379/0` |
| `BIGRAG_VECTOR_STORE_PROVIDER` | Vector backend: `qdrant`, `s3_vectors`, or `turbopuffer`. | `qdrant` |
| `BIGRAG_QDRANT_URL` | Qdrant connection URL. | `http://localhost:6333` |
| `BIGRAG_QDRANT_API_KEY` | Optional Qdrant API key. | — |
| `BIGRAG_QDRANT_CONNECT_TIMEOUT_SECONDS` | Qdrant startup connection timeout. | `10` |
| `BIGRAG_QDRANT_REQUIRED` | Fail startup if the configured vector store cannot be reached. | `false` |
| `BIGRAG_MASTER_KEY` | Fernet key for encrypted provider secrets, instance-setting secrets, embedding-cache rows, and Redis cache payloads. Required for production. | — |
| `BIGRAG_MASTER_KEY_PREVIOUS` | JSON array of old Fernet keys during staged key rotation. | `[]` |
| `BIGRAG_UPLOAD_DIR` | Local document upload directory when storage backend is `local`. | `./data/uploads` |

`BIGRAG_DATABASE_URL` preserves Postgres `sslmode` settings. Use `sslmode=require`, `verify-ca`, or `verify-full` for hosted Postgres TLS; use `sslmode=disable` only for local or trusted private networks.

`BIGRAG_MASTER_KEY_PREVIOUS` is dual-read during rotation for encrypted secrets and API-key hash lookup. Keep old keys there until encrypted rows and minted API keys have been rewritten or replaced.

The admin UI has one frontend bootstrap value: point it at the API with `VITE_BIGRAG_URL` at build/dev time or `BIGRAG_URL` in the app container when frontend and backend are deployed separately.

## TOML bootstrap file

The CLI can also read a `bigrag.toml` file. Keep this file to bootstrap wiring:

```toml
env = "prod"
host = "0.0.0.0"
port = 4000
workers = 1

database_url = "postgres://bigrag:change-me@postgres:5432/bigrag?sslmode=disable"
redis_url = "redis://redis:6379/0"
vector_store_provider = "qdrant"
qdrant_url = "http://qdrant:6333"
qdrant_api_key = ""

master_key = "generate-a-fernet-key"
master_key_previous = []

upload_dir = "./data/uploads"
```

Environment variables override TOML values. CLI flags passed to `python -m bigrag.main` override both.

## Runtime settings

After the first admin account exists, go to `/settings` to manage runtime settings. Runtime settings are stored in Postgres in the `instance_settings` table. Secret settings are encrypted with `BIGRAG_MASTER_KEY` and redacted on read.

The same surface is available through [`/admin/settings`](/docs/api-reference/instance-settings).

| Area | Examples |
|------|----------|
| Security | CORS origins, trusted proxies, session cookie policy, provider URL allow-lists, embedding-cache mode, private-network escape hatches. |
| Data | Storage backend, vector-store provider, upload limits, OCR, ingestion workers, queue depth, webhook delivery limits, and retention windows. |
| Models | Default embedding provider, model, dimension, key, base URL, cache TTLs, chat provider, chat model, temperature, history count, and context budget. |
| Backups | S3-compatible readable backup bucket, endpoint, region, prefix, and credentials for S3, R2, or MinIO. |

The UI shows common controls first and keeps raw setting keys, source metadata, restart markers, and rarely changed limits in Advanced controls. Legacy deep links such as `/settings?tab=storage`, `/settings?tab=vector_store`, `/settings?tab=search`, and `/settings?tab=chat` still open the relevant panel inside the redesigned workspace.

Some settings apply immediately. Settings that affect process startup or long-lived clients are marked in Advanced controls.

<Callout type="info">
Legacy runtime environment variables are still read as initial defaults for compatibility, but enterprise installs should treat `/settings` as the control plane after bootstrap.
</Callout>

## CLI flags

`python -m bigrag.main` accepts bootstrap overrides:

```bash
--config PATH            Path to bigrag.toml
--host HOST              Override server host
--port PORT              Override server port
--database-url URL       Override Postgres URL
--qdrant-url URL         Override Qdrant URL
--redis-url URL          Override Redis URL
```
