Base path: `/v1/admin` — Session-only. Audit records are immutable.

bigRAG maintains two separate operational trails:

- **`audit_log`** — privileged state changes and selected operator/retrieval actions: API-key creation, collection mutations, evaluation runs, and vector writes.
- **`access_log`** — RAG calls with actor, auth method, endpoint, status, collection context, and latency. Includes query, batch query, vector mutation, and evaluation calls; excludes admin UI refreshes and admin/control-plane reads. Request bodies, raw prompts, document content, secrets, and credentials are never stored.

<Accordion title="GET /v1/admin/audit — List audit entries">

```
GET /v1/admin/audit
```

**Query parameters:**

| Parameter | Type | Notes |
|-----------|------|-------|
| `action` | string | Exact match, e.g. `api_key.create` |
| `actor_id` | UUID | Filter by user UUID — must be a valid UUID, not an email |
| `resource_type` | string | e.g. `collection`, `document`, `api_key`, `user`, `webhook` |
| `limit` | integer | 1–1,000, default 100 |
| `offset` | integer | Default 0 |

<Callout type="info">
  Date-range filtering isn't yet supported — paginate and filter `created_at` client-side if you need a time window.
</Callout>

**Response** `200`:

```json
{
  "entries": [
    {
      "id": "9f2a…",
      "actor_id": "c71f…",
      "actor_email": "admin@example.com",
      "api_key_id": null,
      "action": "api_key.create",
      "resource_type": "api_key",
      "resource_id": "b0f8…",
      "metadata": { "name": "ingestion-worker", "scopes": ["document:*"] },
      "ip": "203.0.113.5",
      "user_agent": "Mozilla/5.0 …",
      "created_at": "2026-04-12T10:21:44Z"
    }
  ],
  "total": 42
}
```

**Field notes:**

- `actor_id` / `actor_email` — the admin account that performed the action. Both are `null` for system-initiated events (e.g. cleanup workers).
- `api_key_id` — populated when the action was performed via an API key; holds the key's UUID, and `actor_id` is the owning admin. `null` for session-cookie (admin UI) calls.
- `metadata` — per-action context (never credentials or document content). Shape varies by `action` — e.g. `api_key.create` includes `name` and `scopes`.

**Currently emitted actions:**

| Action family | Emitted by |
|---------------|------------|
| `auth.*` | Setup, login success/failure, logout, logout-all |
| `user.*` | User create, update, delete, password change |
| `api_key.*` | API-key create, update, rotate, delete |
| `mcp_server.*` | MCP server create, update, rotate, delete |
| `collection.*` | Collection create, update, re-embed, truncate, delete |
| `document.*` and `upload_session.*` | Upload, batch upload/delete, reprocess, upload-session lifecycle |
| `webhook.*` | Webhook create, update, delete, test, delivery replay |
| `embedding_preset.*` | Preset create, update, delete |
| `instance_settings.*` and `embedding_cache.purge` | Runtime settings updates, resets, and cache purge |
| `backup.requested` | Readable backup request |
| `query.*`, `vectors.*`, `analytics.read`, `evaluation.run`, `chat.*` | Retrieval, vector, analytics, evaluation, and chat actions |

Use the structured application log stream alongside the audit log when you need full request diagnostics, raw route timing, or operational events outside the audit action vocabulary.

</Accordion>

<Accordion title="GET /v1/admin/access/overview — Access overview">

Session-only admin endpoint.

```
GET /v1/admin/access/overview
```

**Query parameters:**

| Parameter | Type | Notes |
|-----------|------|-------|
| `window_days` | integer | 1-90, default 7 |

**Response** `200` includes total RAG events, success/error rate, average and p95 latency, query event count, action buckets, latency-by-action buckets, a timeline, and the most recent access rows.

</Accordion>

<Accordion title="GET /v1/admin/access/logs — List access logs">

```
GET /v1/admin/access/logs
```

**Query parameters:**

| Parameter | Type | Notes |
|-----------|------|-------|
| `action` | string | Exact action match, e.g. `query.run` or `vectors.upsert` |
| `actor_id` | UUID | Filter by user UUID |
| `collection` | string | Exact collection name |
| `method` | string | HTTP method |
| `path` | string | Case-insensitive path contains match |
| `status_family` | string | `2xx`, `3xx`, `4xx`, or `5xx` |
| `success` | boolean | `true` for 2xx/3xx, `false` for 4xx/5xx |
| `limit` | integer | 1-1,000, default 100 |
| `offset` | integer | Default 0 |

Access-log rows include actor/API-key identity when available, route/path, status code, latency, IP, user-agent, request ID, collection context, and safe metadata such as query hash, query length, top-k, result count, evaluation metrics, and cache use.

</Accordion>
