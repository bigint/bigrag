---
title: Audit Log
description: Read the immutable audit trail of admin actions.
---

Base path: `/v1/admin`

Session-only. Audit records are immutable.

## List Audit Entries

```
GET /v1/admin/audit
```

**Query parameters:**

| Parameter | Type | Notes |
|-----------|------|-------|
| `action` | string | Exact match, e.g. `api_key.create` |
| `actor_id` | UUID | Filter by user UUID — must be a valid UUID, not an email |
| `resource_type` | string | e.g. `collection`, `document`, `api_key`, `user`, `webhook` |
| `limit` | integer | 1–1,000, default 100 |
| `offset` | integer | Default 0 |

Date-range filtering isn't yet supported — paginate and filter `created_at` client-side if you need a time window.

**Response** `200`:

```json
{
  "entries": [
    {
      "id": "9f2a…",
      "actor_id": "c71f…",
      "actor_email": "admin@example.com",
      "api_key_id": null,
      "action": "api_key.create",
      "resource_type": "api_key",
      "resource_id": "b0f8…",
      "metadata": { "name": "ingestion-worker", "scopes": ["document:*"] },
      "ip": "203.0.113.5",
      "user_agent": "Mozilla/5.0 …",
      "created_at": "2026-04-12T10:21:44Z"
    }
  ],
  "total": 42
}
```

### Field notes

- `actor_id` / `actor_email` identify the admin account that performed the action. Both are `null` for system-initiated events (e.g. cleanup workers).
- `api_key_id` is populated when the action was performed via an API key — the field holds the key's UUID, and `actor_id` is the admin who owns the key. For session-cookie (Studio) calls, `api_key_id` is `null`.
- `metadata` is per-action context (never credentials or document content). Shape varies by `action` — e.g. `api_key.create` includes `name` and `scopes`.

### Currently emitted actions

| Action | Emitted by |
|--------|-----------|
| `api_key.create` | `POST /v1/admin/api-keys` |
| `mcp_server.create` | `POST /v1/admin/mcp-servers` |
| `mcp_server.rotate` | `POST /v1/admin/mcp-servers/{id}/rotate` |

Audit emission is **not yet wired into every privileged endpoint** — login/logout, user CRUD, API-key updates and deletes, collection mutations, document mutations, and webhook mutations are not currently recorded. Use the application logs (`bigrag.routers.*`) as a secondary trail until coverage expands.

If you have a compliance requirement that depends on this, prefer scraping the structured `bigrag` log stream alongside the audit log until the gap is closed.
