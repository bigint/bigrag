Base path: `/v1/admin/backups`

Readable backups export Postgres rows and vector-store points to an S3-compatible bucket. Vector-store points are written to JSONL as each provider page arrives, so backup memory usage does not grow with the full vector collection size. bigRAG does not expose restore endpoints.

<Callout type="warn">
  Backups are plain JSON, JSONL, and SQL — not client-side encrypted. Treat the destination bucket as sensitive. Secret-bearing database columns and embedding-cache vectors are redacted during export.
</Callout>

<Accordion title="GET /v1/admin/backups/{backup_id} — Get backup">

```http
GET /v1/admin/backups/{backup_id}
```

Returns one backup job or `404` if it does not exist.

</Accordion>

<Accordion title="POST /v1/admin/backups — Start backup">

```http
POST /v1/admin/backups
Content-Type: application/json

{ "label": "Before model migration" }
```

Creates a backup job and enqueues it on the Dramatiq backup worker. Only one backup can be pending or running at a time.

While the job runs, bigRAG acquires a maintenance lock:

- Mutating API requests are rejected with `423`
- New ingestion jobs are rejected
- Dramatiq ingestion and connector actors delay themselves
- Scheduled S3 syncs do not start

The backup fails if:

- The backup bucket settings are incomplete or invalid
- Turbopuffer cannot be reached

Returns `409` when another backup or maintenance lock is active.

</Accordion>

<Accordion title="GET /v1/admin/realtime/backups — Realtime stream">

```http
GET /v1/admin/realtime/backups
```

Session-cookie SSE stream used by the admin UI. Each `snapshot` payload has the same shape as `GET /v1/admin/backups`. Refreshes quickly while jobs are pending or running.

</Accordion>

## Object layout

Each backup is written below:

```txt
{backup_s3_prefix}/backups/{backup_id}/
```

Objects:

```txt
manifest.json
checksums.json
postgres/schema.sql
postgres/tables/{table}.jsonl
vector_store/collections.json
vector_store/points/{collection_name}.jsonl
```

`manifest.json` includes the app version, format version, generated timestamp, destination details without secrets, table counts, per-collection vector-store export metadata, vector counts, object count, byte count, `"encryption": "redacted"`, and a `redaction` summary.
