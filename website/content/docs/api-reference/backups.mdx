---
title: Backups
description: Admin endpoints for readable S3-compatible full-instance backups.
---

Readable backups export Postgres rows, vector-store points, and uploaded source files to an S3-compatible bucket. They are backup-only; bigRAG does not expose restore endpoints.

Backups are plain JSON, JSONL, SQL, and raw files. They are not client-side encrypted, so the destination bucket must be treated as sensitive. Secret-bearing database columns and embedding-cache vectors are redacted during export.

Base path: `/v1/admin/backups`

## List backups

```http
GET /v1/admin/backups
```

Query parameters:

| Name | Type | Default | Notes |
|------|------|---------|-------|
| `limit` | integer | `20` | 1-100 |
| `offset` | integer | `0` | Pagination offset |

## Get backup

```http
GET /v1/admin/backups/{backup_id}
```

Returns one backup job or `404` if it does not exist.

## Start backup

```http
POST /v1/admin/backups
Content-Type: application/json

{ "label": "Before model migration" }
```

Creates a backup job and enqueues it on the Dramatiq backup worker. Only one backup can be pending or running at a time.

While the job runs, bigRAG acquires a maintenance lock. Mutating API requests are rejected with `423`, new ingestion jobs are rejected, Dramatiq ingestion and connector actors delay themselves, and scheduled Google Drive syncs do not start.

The backup fails if:

- The backup bucket settings are incomplete or invalid.
- A configured vector-store client cannot be reached.
- A stored upload file referenced by a document row is missing.

## Realtime stream

```http
GET /v1/admin/realtime/backups
```

Session-cookie SSE stream used by the admin UI. Each `snapshot` payload has the same shape as `GET /v1/admin/backups`.

## Object layout

Each backup is written below:

```txt
{backup_s3_prefix}/backups/{backup_id}/
```

Objects:

```txt
manifest.json
checksums.json
postgres/schema.sql
postgres/tables/{table}.jsonl
vector_store/collections.json
vector_store/points/{collection_name}.jsonl
uploads/{collection}/{document_id}.{ext}
```

`manifest.json` includes the app version, format version, generated timestamp, destination details without secrets, table counts, per-collection vector-store export metadata, vector counts, upload counts, object count, byte count, `"encryption": "redacted"`, and a `redaction` summary.
