---
title: User Preferences
description: Per-user JSON blob for Studio UI state.
---

Base path: `/v1/auth/preferences`

Session-only. This is a JSON scratch-pad scoped to the logged-in user — Studio UI uses it to persist sidebar state, default collection filter, preferred search mode, and similar client-side prefs. The server does not interpret the payload.

## Get Preferences

```
GET /v1/auth/preferences
```

**Response** `200`:

```json
{
  "data": {
    "sidebar_collapsed": false,
    "default_collection": "knowledge_base",
    "playground": { "search_mode": "hybrid", "top_k": 10 }
  }
}
```

New users return `{"data": {}}`.

## Update Preferences

```
PUT /v1/auth/preferences
```

Shallow-merges the request body into the stored preferences. Top-level keys in the request are overwritten; keys not present in the request are preserved. Send an explicit `null` to clear a single key.

```json
{ "data": { "default_collection": "knowledge_base" } }
```

The body may be either `{"data": {...}}` or a bare object — both are accepted.

**Response** `200`: echoes the merged `data`.

Sensitive paths (currently `playground.openai_key`) are Fernet-encrypted at rest when `BIGRAG_ENCRYPTION_KEY` is configured, and decrypted on `GET`.

There is no size validation beyond the standard request-body limit, but keep payloads small (&lt;64 KB) — this isn't a document store.
