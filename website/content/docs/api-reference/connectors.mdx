---
title: Connectors
description: Provider-neutral connector configuration, OAuth, source selection, and resync APIs.
---

Cloud connectors import remote files into the normal bigRAG document pipeline. The connector core owns provider config, user accounts, sources, sync jobs, manifests, scheduling, document replacement, and remote deletion handling. Provider adapters own OAuth details, remote listing, export/download behavior, and provider-specific metadata.

Google Drive is the first provider and uses the `google` route slug with `google_drive` as the stored provider id. Future providers such as SharePoint or OneDrive should plug into the same route shape instead of cloning the source and sync job flow.

## Admin Provider Config

```
GET /v1/admin/connectors/{provider}
PUT /v1/admin/connectors/{provider}
```

Session-only admin endpoints. For Google Drive, use `/v1/admin/connectors/google`. The `PUT` body stores OAuth credentials:

```json
{
  "enabled": true,
  "client_id": "…apps.googleusercontent.com",
  "client_secret": "…"
}
```

Responses mask secret values and include `callback_url`, which must be registered with the provider. Google Drive returns a callback URL ending in `/v1/connectors/google/oauth/callback`.

## User Connection

```
GET /v1/connectors/{provider}/account
GET /v1/connectors/{provider}/oauth/start?redirect_path=/collections/docs/documents
GET /v1/connectors/{provider}/oauth/start-url?redirect_path=/collections/docs/documents
GET /v1/connectors/{provider}/oauth/callback
POST /v1/connectors/{provider}/disconnect
```

These endpoints require session authentication. For Google Drive, the OAuth flow uses `openid email profile` and `https://www.googleapis.com/auth/drive.readonly` so bigRAG can render an in-app Drive browser and sync selected files/folders.

## Drive Browser

```
GET /v1/connectors/{provider}/files?parent_id=root
GET /v1/connectors/{provider}/files?query=handbook
```

Returns the connected user's visible remote files and folders, plus whether each item is supported by the ingestion pipeline. For Google Drive, native Docs, Sheets, and Slides are exported to DOCX, XLSX, and PPTX before ingestion.

## Sources

```
GET /v1/connectors/{provider}/sources?collection=docs
POST /v1/connectors/{provider}/sources
PATCH /v1/connectors/{provider}/sources/{source_id}
DELETE /v1/connectors/{provider}/sources/{source_id}
POST /v1/connectors/{provider}/sources/{source_id}/sync
GET /v1/connectors/{provider}/sync-jobs?collection=docs&source_id=…
```

Create a source from an in-app browser selection:

```json
{
  "collection_name": "docs",
  "root_id": "drive-file-or-folder-id",
  "root_name": "Handbook",
  "root_mime_type": "application/vnd.google-apps.folder",
  "source_type": "folder",
  "metadata": { "team": "ops" }
}
```

New sources start an initial sync and default to daily scheduled resync. Manual syncs detect additions, updates, and remote removals. Google Drive folder sync scans nested folders with bounded concurrency before downloading supported files. If a provider returns a successful listing and a previously synced file is missing, bigRAG deletes the document, vectors, stored file, and connector manifest row.

Sync jobs can be filtered by `collection`, `source_id`, and `limit`. While a Google Drive job runs, `details.progress` reports Drive-sync progress only:

```json
{
  "phase": "syncing",
  "message": "Syncing Contract.pdf",
  "current_item_name": "Contract.pdf",
  "current_item_id": "drive-file-id",
  "progress_percent": 50,
  "processed_items": 1,
  "total_items": 2,
  "counts": {
    "created": 1,
    "updated": 0,
    "skipped": 0,
    "deleted": 0,
    "failed": 0
  }
}
```

Terminal `complete` jobs mean Drive files were scanned, downloaded or updated, remote deletions were applied, and changed documents were queued for the normal ingestion pipeline. Conversion, chunking, embedding, and indexing continue through document status progress.
