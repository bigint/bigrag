Connectors import remote files into the normal bigRAG document pipeline. The S3 connector mirrors bucket prefixes into collections and uses the same document conversion, chunking, embedding, indexing, progress, and cleanup surfaces as direct uploads.

The first provider is S3-compatible object storage. Use the `s3` route slug for AWS S3, Cloudflare R2, MinIO, and compatible services.

<Accordions type="multiple">

<Accordion title="Sources — create, update, delete">

These endpoints require an admin session.

```
GET /v1/connectors/s3/sources?collection=docs
POST /v1/connectors/s3/sources
PATCH /v1/connectors/s3/sources/{source_id}
DELETE /v1/connectors/s3/sources/{source_id}
```

Create a bucket-prefix source:

```json
{
  "collection_name": "docs",
  "bucket": "company-knowledge",
  "prefix": "policies/",
  "region": "us-east-1",
  "endpoint_url": null,
  "force_path_style": false,
  "access_key_id": "AKIA...",
  "secret_access_key": "...",
  "session_token": null,
  "schedule_enabled": true,
  "sync_interval_hours": 24,
  "metadata": { "team": "ops" }
}
```

bigRAG validates the credentials by listing the configured prefix before saving the source. Responses include bucket, prefix, region, endpoint URL, path-style setting, schedule state, sync state, timestamps, and `has_credentials`; secret values are never returned.

`PATCH` can update bucket, prefix, region, endpoint URL, path-style mode, schedule settings, metadata, and credentials. `access_key_id` and `secret_access_key` must be sent together when rotating credentials.

</Accordion>

<Accordion title="Sync jobs — manual and scheduled prefix mirroring">

```
POST /v1/connectors/s3/sources/{source_id}/sync
GET /v1/connectors/s3/sync-jobs?collection=docs&source_id=...
```

New sources start an initial sync. Sources default to daily scheduled sync unless `schedule_enabled` is false. Manual and scheduled syncs mirror the prefix:

- new supported objects create documents
- changed objects replace existing documents and queue re-ingestion
- missing remote objects delete the document, vectors, staged file, and connector manifest row
- failed listings fail the job without deleting existing documents

Sync jobs can be filtered by `collection`, `source_id`, and `limit`. Running jobs include `details.progress`:

```json
{
  "phase": "syncing",
  "message": "Syncing Contract.pdf",
  "current_item_name": "Contract.pdf",
  "current_item_id": "s3://company-knowledge/policies/Contract.pdf",
  "progress_percent": 50,
  "processed_items": 1,
  "total_items": 2,
  "counts": {
    "created": 1,
    "updated": 0,
    "skipped": 0,
    "deleted": 0,
    "failed": 0
  }
}
```

Terminal `complete` jobs mean S3 objects were listed, changed files were staged for ingestion, remote deletions were applied, and changed documents were queued for the normal ingestion pipeline.
