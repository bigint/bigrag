## Production hardening checklist

Tick these off before pointing real traffic at a rag.computer deployment:

- [ ] `RAG_COMPUTER_ENV=prod` — enables the startup guard.
- [ ] `RAG_COMPUTER_MASTER_KEY` set to a 32-byte Fernet key (see [Encryption at rest](/docs/deployment/encryption)).
- [ ] Rotate `POSTGRES_PASSWORD` from the shipped default (`rag-computer`).
- [ ] `RAG_COMPUTER_SESSION_COOKIE_SECURE=true` and terminate TLS at your
  reverse proxy (nginx, Caddy, Traefik, Cloudflare).
- [ ] `RAG_COMPUTER_CORS_ORIGINS` set to an explicit list of your admin UI /
  app origins — no `*`.
- [ ] `RAG_COMPUTER_TRUSTED_PROXIES` set to the CIDRs of your own reverse
  proxies if rag.computer sits behind nginx, Caddy, Traefik, or a load balancer.
- [ ] Redis with `requirepass` set and `appendonly yes` persisted to
  a mounted volume.
- [ ] Qdrant cluster mode, S3 Vectors, or turbopuffer if you expect >10M vectors or need managed HA.
- [ ] Postgres warm-standby replica for failover.
- [ ] Backup strategy: configure readable S3/R2 backups in Settings → Backups,
  protect that bucket as sensitive, and separately keep encrypted infrastructure
  snapshots for Postgres, the configured vector store, Redis, and uploads.
- [ ] Set `metadata_schema` on collections that accept untrusted
  metadata so uploads with invalid shape are rejected at the edge.
- [ ] Wire `GET /v1/admin/audit` into your SIEM / log pipeline.
- [ ] Configure webhooks to your monitoring stack for
  `document.failed` events so ingestion errors don't sit silently.

## Startup safety guard

rag.computer refuses to boot when `RAG_COMPUTER_ENV=prod` is set **and** any of the following
insecure defaults are still active. Setting `RAG_COMPUTER_ENV=prod` in production catches
config mistakes that would otherwise ship silently:

- `RAG_COMPUTER_SESSION_COOKIE_SECURE` is `false` — set to `true` so cookies are HTTPS-only.
- `RAG_COMPUTER_DATABASE_URL` still uses the shipped `rag_computer:rag_computer` credentials — rotate the Postgres password.
- `RAG_COMPUTER_MASTER_KEY` is unset — rag.computer needs a Fernet key to envelope-encrypt provider credentials, embedding-cache rows, and Redis cache payloads. See [Encryption at rest](/docs/deployment/encryption).
- `RAG_COMPUTER_HOST` binds to `0.0.0.0` or `::` without `RAG_COMPUTER_ALLOW_PUBLIC_BIND_IN_PROD=true` after you have confirmed the service sits behind TLS and a network boundary.
- `RAG_COMPUTER_SESSION_COOKIE_DOMAIN` is set while `RAG_COMPUTER_TRUSTED_PROXIES` is empty.

When the guard trips, it logs every violation before exiting so you can fix the whole
list in one edit. If you intentionally want to run with the development defaults (e.g.
on a private network behind a VPN), leave `RAG_COMPUTER_ENV` unset or set it to `dev`.

## Recommended Settings

```bash
# Mode
RAG_COMPUTER_ENV=prod                     # refuses to boot with insecure defaults

# Sessions
RAG_COMPUTER_SESSION_COOKIE_SECURE=true   # HTTPS-only
RAG_COMPUTER_SESSION_COOKIE_SAMESITE=lax      # use none when API and admin UI are cross-site
RAG_COMPUTER_CORS_ORIGINS=["https://admin.example.com"]
RAG_COMPUTER_TRUSTED_PROXIES=["10.0.0.0/8"]  # your reverse-proxy/load-balancer CIDRs

# Auth is admin accounts + minted ragc_sk_ keys.
# Bootstrap with POST /v1/auth/setup, then mint service keys at /v1/admin/api-keys.

# Infrastructure
RAG_COMPUTER_DATABASE_URL=postgres://user:pass@host:5432/rag_computer?sslmode=require
RAG_COMPUTER_REDIS_URL=redis://redis:6379/0

# Performance
RAG_COMPUTER_WORKERS=8                    # Match CPU cores
RAG_COMPUTER_INGESTION_WORKERS=8          # More workers for heavy ingestion
RAG_COMPUTER_DB_POOL_MAX=100              # Increase for high concurrency
RAG_COMPUTER_EMBEDDING_CONCURRENCY=16     # Parallel embedding requests
RAG_COMPUTER_QDRANT_SEARCH_EF=128         # Optional HNSW recall/latency tuning

# Storage
RAG_COMPUTER_UPLOAD_DIR=/data/uploads
```

<Callout type="warn">
  Never commit secrets (API keys or database passwords) to version control. Use a `.env` file, Docker secrets, or a secrets manager like AWS Secrets Manager or HashiCorp Vault.
</Callout>

```toml
upload_dir = "./data/uploads"
```

## Readable backups

The admin UI can create backup-only full-instance exports from Settings → Backups.
The destination is S3-compatible, so AWS S3, Cloudflare R2, and MinIO all work.
Use a bucket or prefix dedicated to backups rather than reusing the upload bucket.

Readable backups are plain JSON, JSONL, SQL, and raw files. They include Postgres
rows, vector-store points and payloads, uploaded files, chats, and logs. Provider
secrets, token/hash columns, S3 credentials, and embedding-cache vectors are
redacted. They are useful for inspection and data portability, but they are not a
substitute for encrypted infrastructure snapshots or tested disaster recovery
runbooks.

## Logging

Backend logging is always enabled at debug level with text output. It is not controlled
through environment variables or CLI flags.

API logs are emitted through `structlog` with stable event names and key-value
fields for request, ingestion, vector-store, webhook, and auth activity. Secrets
are redacted before log rendering.

## Troubleshooting

### Connection refused on startup

Ensure all infrastructure services are running and healthy:

```bash
docker exec rag-computer-postgres pg_isready -U rag_computer
curl -f http://localhost:6333/healthz
docker exec rag-computer-redis redis-cli ping
```

### Documents stuck in "pending"

- Verify Redis is running and accessible
- Check backend logs for worker errors
- Ensure `RAG_COMPUTER_INGESTION_WORKERS` is > 0

### Dimension mismatch on query

The query embedding dimension doesn't match the collection's configured dimension. Ensure you're querying with the same embedding model.

### File upload returns 413

File exceeds the max upload size. Increase `RAG_COMPUTER_MAX_UPLOAD_SIZE_MB`.

### `/health/ready` returns 503 but services are running

The readiness endpoint also checks the embedding provider. If no collection has an `embedding_api_key` configured, it reports degraded status. Check `/health` first to confirm the server itself is running, then create a collection with a valid embedding key.

### Document uploads fail with embedding errors

Ensure the collection has a valid `embedding_api_key` set. You can provide it when creating the collection or set `RAG_COMPUTER_EMBEDDING_API_KEY` as a server-wide default.

### Slow embedding performance

- Increase `RAG_COMPUTER_INGESTION_BATCH_SIZE` for better throughput
- Increase `RAG_COMPUTER_EMBEDDING_CONCURRENCY` for more parallelism
