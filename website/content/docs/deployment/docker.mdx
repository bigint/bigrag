## Quick Start

<Steps>
<Step>
### Pull the image

```bash
docker pull yoginth/rag-computer:2026.4.30
```
</Step>
<Step>
### Start the stack

```bash
docker compose up -d
```

This starts rag.computer API, Postgres, Redis, and Qdrant.
</Step>
<Step>
### Verify

```bash
curl http://localhost:4000/health
```
</Step>
</Steps>

## Docker Compose

The default `docker-compose.yml` runs Qdrant as a single service. Qdrant does not require etcd for this standalone setup.

```yaml
services:
  rag-computer:
    image: yoginth/rag-computer:2026.4.30
    ports:
      - "4000:4000"
    volumes:
      - rag_computer_data:/data
    environment:
      RAG_COMPUTER_ENV: "${RAG_COMPUTER_ENV:-dev}"
      RAG_COMPUTER_DATABASE_URL: postgres://rag_computer:rag_computer@postgres:5432/rag_computer?sslmode=disable
      RAG_COMPUTER_QDRANT_URL: http://qdrant:6333
      RAG_COMPUTER_REDIS_URL: redis://redis:6379/0
      RAG_COMPUTER_SESSION_COOKIE_SECURE: "${RAG_COMPUTER_SESSION_COOKIE_SECURE:-false}"
      RAG_COMPUTER_CORS_ORIGINS: '${RAG_COMPUTER_CORS_ORIGINS:-["http://localhost:3000"]}'
      RAG_COMPUTER_UPLOAD_DIR: /data/uploads
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy
      qdrant:
        condition: service_started

  postgres:
    image: postgres:17
    environment:
      POSTGRES_USER: rag_computer
      POSTGRES_PASSWORD: rag_computer
      POSTGRES_DB: rag_computer
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U rag_computer"]
      interval: 10s
      timeout: 5s
      retries: 5

  qdrant:
    image: qdrant/qdrant:v1.17.1
    ports:
      - "6333:6333"
      - "6334:6334"
    volumes:
      - qdrant_data:/qdrant/storage

  redis:
    image: redis:7-alpine
    command: redis-server --appendonly yes
    volumes:
      - redis_data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  rag_computer_data:
  postgres_data:
  qdrant_data:
  redis_data:
```

## Admin UI Image

The admin UI is a static Vite app served by Nginx. Build it from the repository root:

```bash
docker build -f app/Dockerfile -t rag-computer-admin-ui .
```

Run it with the API URL and matching backend CORS origin:

```bash
docker run --rm -p 3000:3000 \
  -e RAG_COMPUTER_URL=http://localhost:4000 \
  rag-computer-admin-ui
```

Set `RAG_COMPUTER_CORS_ORIGINS='["http://localhost:3000"]'` on the API when running the UI locally. In production, set the exact public admin UI origin and use secure cookies.

## Health Checks

rag.computer exposes two health endpoints:

| Endpoint | Purpose | Notes |
|----------|---------|-------|
| `/health` | Liveness check | Always returns `200` if the server is running |
| `/health/ready` | Readiness check | Returns `503` if Postgres, Redis, the configured vector store, or the embedding provider is unreachable |

```bash
# Quick liveness check
curl http://localhost:4000/health

# Full readiness (checks all dependencies)
curl http://localhost:4000/health/ready

# Infrastructure services
docker exec rag-computer-postgres pg_isready -U rag_computer
curl -f http://localhost:6333/healthz
docker exec rag-computer-redis redis-cli ping
```

<Callout type="warn">
  `/health/ready` also validates the embedding provider. If no collection has an `embedding_api_key` configured, it returns `503`. Use `/health` if you just need to check the server is running.
</Callout>

## Startup Troubleshooting

If the API exits with `ImportError: Can't find Python file .../site-packages/alembic/env.py`, rebuild or pull a current API image. The container must include the bundled Alembic environment so startup migrations can run before FastAPI begins serving traffic.
